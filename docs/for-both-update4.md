## 1. 進捗

- **S2-0 を ALTERNA の VM で部分実行しました。**
  - 本番と同一構成をローカル再現:Paper 26.3-259 + Geyser-Spigot 2.12.1-b1307（固定済み jar)+ JDK 25。
  - Geyser 拡張の骨格を実装・コンパイル完了:カスタム定義 `vivecraftbedrockbridge:vr_avatar` の登録、float プロパティ 29 個（[-360, 360]）の登録、`ServerSpawnEntityEvent` で UUID を照合して定義を差し替えるハンドラ（照合用レジストリは仮置きとしてファイル読み）。
  - 結果:**拡張は本番ビルド上でロード・有効化まで確認**。ただし Geyser 本体の初期化が VM 環境で完走しませんでした。原因は特定済みで、Geyser が暗号化まわりの discovery 情報を取得する際、VM の出口プロキシと Java の CONNECT トンネリングが相性不良を起こすためです（同じ URL は Python からは取得可能）。コードの問題ではなく VM の環境制限で、通常のネットワーク（本人の PC / Altare）では起きません。
  - 残りの S2-0 確認（ハンドラ発火、UUID 照合での差し替え、通常の防具立てへの無影響＝対照実験、Geyser 再起動後の再登録）は、本人の PC で実施予定。検証用環境一式（local-test/)は用意済みです。
- **Altare の障害は継続中**（Console / デプロイ系の Partial outage）。v0.3.1 のデプロイは引き続き待機中です。ゲームサーバー自体は稼働しています。

## 2. 設計判断の修正（あるキドの指摘、2026-11-24）

S2-1（見た目）の準備として、RK3_Vivecraft のスキンを焼き込んだリソースパック骨格を作成しました。その際、あるキドから指摘がありました:

> 「リソパのジオメトリって俺じゃなくて、Vivecraft 入れて入ってる人のやつじゃないとだめなんじゃ」

正しい指摘です。マネキンが表すのは **VR プレイヤー本人** であり、見た目もその人のものでなければ意味がありません（テスターが VR で参加する場合、その人の姿で見える必要があります）。設計を次のように修正しました:

- **ジオメトリは全員共通**（人型の形はスキンに依存しない）。`geometry.vivecraftbedrockbridge.vr_avatar`、Java スキンの UV 配置に一致する box UV、classic（腕4px)。
- **テクスチャとクライアントエンティティ定義は VR プレイヤーごとに1セット**:
  - 定義 ID:`vivecraftbedrockbridge:vr_avatar_<プレイヤー名小文字>`
  - テクスチャ:`textures/entity/vr_avatar_<プレイヤー名小文字>.png`
  - 登録済みは rk3_vivecraft の分のみ（= 1人目）。
- スキンは Mojang API から取得して焼き込む（動的同期が不可なのは Stage 2 調査の結論どおり）。VR プレイヤーが増えたらその人の分を追加し、パックを再生成する。再配布は Geyser が Bedrock の参加時に行う。
- 拡張側は、既存の「マネキンUUID → 所有者プレイヤー」の対応から、所有者用の定義を選んで割り当てる。
- slim 型（腕3px）のプレイヤー用ジオメトリは未作成。必要になったら追加する、としています。

## 3. レビューしてほしい点

1. **プレイヤーごとの定義を増やす方式**に問題はないか。VR プレイヤーが将来たとえば数十人規模になった場合、定義登録やパックサイズの面で破綻しないか。
2. **定義の選び分けのタイミング**:`ServerSpawnEntityEvent` は Bedrock セッションごとのスポーンで発火します。その時点で「マネキンUUID → 所有者 → 定義ID」が引ける必要があります。プラグインと拡張で classloader が別という共有問題（S2-0 で検証予定）と合わせて、より良い引き渡し方法があれば教えてください。
3. **パック再生成と再配布**:運用中に新しい VR プレイヤーが登録された場合、すでに接続中の Bedrock クライアントは再参加するまで新しいテクスチャを持てません。これは許容範囲だと思いますか。強制的に再取得させる手段はありますか。
4. **slim 判定**:Mojang API のスキンメタデータ（model: slim / classic）でプレイヤーごとにジオメトリを選び分ける方針で問題ないか。
5. その他、S2-1 に入る前に直しておくべき点があればお願いします。
