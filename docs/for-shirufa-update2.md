# VivecraftBedrockBridge 続報（第2報）

しるふぁへ。前回のレビューありがとう。対応状況と新しい相談です。

## 1. レビューへの対応（実装済み）

- **v0.1.1**: 指摘された「VRモード解除時にマネキンが残り続ける」バグを修正（tick処理で対象外になった所有者のマネキンを除去）。防具立てに setCollidable(false) も追加。setMarker は GeyserIntegratedPack の挙動確認後に判断、という留保はそのまま維持
- **v0.2.0**: 提案どおりデモモードを実装。config に `demo-mode`（デフォルト false）を追加し、ON の間は非VRプレイヤーにもマネキンを付けてサイン波の擬似ポーズ（右腕を大きく振る・左腕スイング・足踏み・頭の揺れ）を再生する。同時に Phase 3 の出し分けも先行実装した（Floodgate 判定は API を反射で参照し、コンパイル依存を持たない形。統合版プレイヤーには本体を hideEntity してマネキンを見せ、Java プレイヤーにはマネキンを隠す）
- 運用ルールとして、バージョンごとに CHANGELOG.md と README の開発状況を更新して GitHub に反映することにした（GitHub は v0.2.0 まで同期済み）

## 2. 導入状況（ここが止まっている）

- 検証サーバー（Altare）への jar 導入が、**Altare 側の障害**で失敗し続けている。2026-11-21 から「Heavy demand affecting deployments and the Console」という Partial outage が継続中で、コンソールからのファイルアップロードがネットワークエラーで弾かれる（通算9回連続失敗）
- サーバー自体は正常稼働中（Paper 26.3、VSE / Geyser / Floodgate 有効）。既存環境には一切影響なし
- 障害解消後に「アップロード → 再起動 → demo-mode: true → 再起動 → status 確認」の手順で再開予定

## 3. 新しく分かったこと

- Vivecraft には **NonVR コンパニオン**（現行版は同じ jar に同梱、VR はデフォルト OFF でメニューから有効化）があり、フラット画面の Java プレイヤーでも他人の VR の頭・手の動きが見えることを公式情報で確認した
- そのため配信サーバーの参加ルールは「Java 勢は Vivecraft mod 導入必須（ヘッドセットは不要、NonVR で可）」「統合版勢はプラグイン完成後に追加要件なし」で確定方向
- X（Twitter）で VR テスターの募集文も作成済み（条件: Java版と統合版の両方が遊べること、VR で Vivecraft が動くこと。サーバーが無料枠で弱いことと海外リージョンで ping が高いことも明記）

## 4. 現在作業中（v0.3.0、未リリース）

- Phase 3 の出し分けをデモモード時だけでなく **VR モードにも常時適用** する変更
- 肩位置を「足元＋1.38m 固定」から **head.pos 基準（頭の約0.32m下）** に変更し、股関節も waist メタデータがあればその位置を使うように改修（しゃがみ・seated 対策。レビューの指摘を受けたもの）
- コード編集まで進めた段階で、この相談を挟んでいる。ビルドと公開は回答を見てからにする

## 5. 相談したいこと

1. v0.3.0 の2点（出し分けの VR 常時適用、肩・腰の基準変更）の設計判断は妥当か。特に、出し分け常時適用が Phase 2 の「Java フラット画面での目視確認」に悪影響を与えないか
2. Altare 障害で導入できない間に、先行して進めるべき作業の優先順位（Stage 2 の Geyser カスタムエンティティ＋エンティティプロパティ同期の調査は並行で開始済み）
3. デモ検証が可能になったときの**チェックリスト**（何がどう見えれば合格か、どの順で確認すべきか）の提案
4. その他、現状への指摘
