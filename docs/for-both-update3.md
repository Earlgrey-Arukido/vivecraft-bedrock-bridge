# VivecraftBedrockBridge 続報（第3報・しるふぁ＆ミーナ共通）

お二人へ。前回以降の進捗と、新しく作った Stage 3 設計の共有です。

## 1. ミーナのレビュー → v0.3.1 実装・公開済み

指摘は全点採用し、v0.3.1 として実装・ビルド・GitHub 反映まで完了しました。

- 腕ポーズ計算式を `rx = atan2(-localZ, hypot(localX, localY))` に差し替え（水平付近の破綻対策。符号の最終確認はデモ検証）
- マネキン生成時に `setVisibleByDefault(false)` を設定し、見せる相手だけ showEntity する方式へ（生成直後の表示穴と、本人に自分のマネキンが見える問題を解消）。生成直後は即座に出し分けを適用
- tickCounter を経過 tick 数ベースに修正（出し分け周期とデモの波速が間隔設定に依存しないように）
- Floodgate API の参照は失敗を固定せず、100 tick に1回だけ再試行
- `/vivebridge reload` で更新間隔のスケジュールも再登録
- waist がない場合の体の向きを、頭へ最大約60度/秒で遅れて追従させる改善を追加

## 2. 識別設計の確定（しるふぁの質問への回答を含む）

使用中と同一ビルド（2.12.1-b1307）の Geyser jar を公式から取得し、javap で API の実物を直接確認しました。

- Custom Entity API は使用中ビルドに含まれていた: `CustomEntityDefinition`、登録イベント `GeyserDefineEntitiesEvent`、プロパティ登録イベント `GeyserDefineEntityPropertiesEvent`（`registerFloatProperty(対象, 名前, min, max, 既定値)`）、更新 API `GeyserEntity.updateProperty / updatePropertiesBatched`
- スポーンイベント側: 親の `SessionSpawnEntityEvent` は definition（取得・差し替え）と対象セッションのみだが、Java 側の子イベント **`ServerSpawnEntityEvent` が `uuid()`・`entityId()`・`entityType()` を直接返す**
- 名前に相当するエンティティデータ型は API に存在せず、Bukkit の PDC も Geyser 側イベントからは参照できない → 印付け方式は不採用
- **識別設計は方法A（UUID 紐付け）で確定**: プラグインがスポーンと同期してマネキン UUID を登録し、拡張がイベントの UUID と照合して一致した個体だけ定義を差し替える。マネキンUUID ↔ プレイヤーUUID の対応表は既存の管理マップを拡張する
- jar 自体はバージョン固定の保険として手元に保管済み

## 3. Stage 3（関節）設計を作成

docs/stage3-design.md としてまとめました。要点:

- 入力: VSE メタデータの肘・膝位置（`rightelbow.pos` 等）を直接使う。肩→肘→手（股関節→膝→足）の3点で2セグメントに分解
- 上腕/大腿は体フレームでの絶対回転、前腕/脛は**親ボーンからの相対回転**（`R_f_rel = R_u⁻¹ · R_f`）で送る
- 回転の合成・逆変換は行列/クォータニオンで行い、Euler 変換は最後に1回だけ（Stage 1 の近似式は1セグメント専用のため流用しない）
- ツイスト（軸周りのねじれ）は両セグメントとも最短弧（shortest arc）方式で決定的にする
- 肘・膝には解剖学的クランプ（屈曲角が範囲外なら丸める）を入れ、メタデータのノイズによる反転を防ぐ
- 肘・膝データが取れない場合は相対回転 0 とし、Stage 2 の1セグメント表示にフォールバック
- プロパティは Stage 2 で先行定義する約29個をそのまま使用。全値に unwrap（連続化）を適用
- マイルストーン: S3-1 肘 → S3-2 膝 → S3-3 ツイストとクランプの調整
- 実装は Stage 2 のパイプライン（S2-0 拡張スケルトン〜S2-2 プロパティ駆動の実証）完成後
