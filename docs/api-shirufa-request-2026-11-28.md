## Stage 3 設計書（全文）
作成: 2026-11-24 / 前提: Stage 2 の基盤（カスタムエンティティ + プロパティ同期）
目的: 上腕/前腕・大腿/脛の2セグメント構造で肘・膝の曲がりを統合版に再現する。

### 入力データ（VSE メタデータ）
- 肘・膝: rightelbow.pos / leftelbow.pos / rightknee.pos / leftknee.pos（Location）
- 手・足: righthand.pos / lefthand.pos / rightfoot.pos / leftfoot.pos
- 肩・股関節: 肩 = head.pos の約0.32m下から左右、股関節 = waist 基準
- 注意: 肘・膝パートの有効条件は VSE の FBT モードに依存する（S2-3 で実地確認）。取れない場合は1セグメント近似にフォールバック

### 計算仕様（2セグメント分解）
1. 点列: S（肩）、E（肘）、H（手）のワールド座標
2. 方向: 上腕 du = normalize(E − S)、前腕 df = normalize(H − E)
3. 上腕ボーンの回転 R_u: 静止方向（真下 (0,−1,0)）を du に向ける回転。体のローカル座標系（bodyYaw 基準）で計算
4. 前腕ボーンの回転は親からの相対回転: R_f_rel = R_u⁻¹ · R_f
5. サーバー側では行列（またはクォータニオン）で合成・逆変換し、最後に Bedrock 側の Euler に変換。Euler のまま合成しない
6. ツイスト決定方針（2026-11-24 レビューで改訂）: 静止方向からの最短弧は腕を真上に上げた姿勢（180°）で回転軸が不定になりツイストが跳ぶ。対策: 基本は前フレームの回転からの最短弧で連続性を保ち、基準へ緩く戻す。併せて肘平面の法線、または VSE の .rot でツイストを決める方法も候補。腕が伸びきると肘平面が不定になるため、その場合は前フレーム維持か .rot にフォールバック。クォータニオンは符号連続性のため前フレームとの内積で符号をそろえる
7. 解剖学的クランプ: 肘の屈曲角 = du と df のなす角。屈曲 0〜160° の範囲外はクランプ。膝も同様（後方への反り防止）。伸びきり付近はノイズが出やすいためデッドゾーンを持たせる
8. 座標系と演算順序: R_u・R_f は体フレーム基準、ボーンのレスト方向は -Y で統一。相対回転はクォータニオンで R_u.conjugate().multiply(R_f)
9. unwrap とクランプの順序: unwrap が直せるのは ±180° の巻き戻しのみで、ジンバルロックの不連続は直せない。Euler 分解順は、特異点が到達しにくい姿勢に来る順序を選ぶ（S2-1/2 で確定）。クランプ境界で ±180° の折り返しが起きないよう単位と範囲を明示する

### プロパティ対応
- 上腕・前腕・大腿・脛の各 Euler（絶対/相対）を Stage 2 で先行定義済みの29プロパティで送る。全値に unwrap を適用。更新頻度は 10Hz 目標

### フォールバック
- 肘・膝メタデータが無い場合は前腕・脛の相対回転を 0 にし、1セグメント表示に自動で落ちる
- パック未適用の統合版には Stage 1 の防具立て表示が残る
- 脚の歩行スイング代用（2026-11-25 追加）: 足・膝メタデータが無いプレイヤーでは、大腿・脛を歩行スイングで代用する。水平移動速度からバニラ準拠の limb swing を生成: 位相は移動距離で進め、振幅は速度でスケールし、左右は逆位相。静止時はスイング角 0 へ減衰して両脚まっすぐ立つ。脛には大腿のスイングに連動した簡易屈曲（前に振る局面で軽く曲げる）を付ける。しゃがみ・ジャンプ等の再現は対象外。FBT プレイヤーでは実データを優先し、切替は足・膝メタデータの有無で自動判定する。Stage 1 の防具立て脚ポーズにも同じスイングを適用する

### マイルストーン

- S3-2: 脚の2セグメント化（膝）。しゃがみ・歩行で確認
